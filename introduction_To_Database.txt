2.

2.1 
SQL: Employs a rigid, schema-based relational model, storing data in tables with predefined columns and rows
MongoDB: Uses a flexible, schema-less document model, storing data in JSON-like BSON documents within collections
2.2
SQL: Primarily scales vertically by adding more resources (CPU, RAM) to a single server
MongoDB: Designed for horizontal scalability through sharding
2.3
SQL: Utilizes the Standard Query Language (SQL) for defining, manipulating, and retrieving data.
MongoDB: Uses a rich, JavaScript-based query language (MongoDB Query Language - MQL) for querying and data manipulation.
2.4
SQL: Excels at handling complex relationships between tables using various types of joins (INNER JOIN, LEFT JOIN, etc.),
 ensuring data integrity through foreign keys.
MongoDB: Lacks native support for complex joins across collections like SQL databases
2.5
SQL: Typically performs well for complex queries involving multiple joins and aggregations on structured data
MongoDB: Often performs well with high-volume write operations and handling unstructured 
or semi-structured data due to its flexible schema and document-oriented nature.
